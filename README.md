# UPBIT SIGNAL LAB · v53

개인용 원화마켓 초기 움직임 연구 앱. 모든 현재 KRW 거래쌍의 닫힌 1분봉을 같은 기준 시각으로 분석합니다.

## 순서 탐지

업비트가 생략하는 무거래 분은 시작 가격을 확인할 수 있는 1분봉 API 응답에서만 직전 종가·거래대금 0으로 보완합니다. 조회 실패를 무거래로 취급하지 않습니다.

연속된 60분 데이터에서 처음 45분을 기준으로 삼습니다. 다음 10분 동안 거래대금 평균 1.5배 이상, 증가가 4봉 이상 지속, 후반 저점 유지, 양봉 또는 보합 5봉 이상이면 선행 흔적으로 봅니다. 마지막 5분에서 소폭 돌파와 유지, 거래대금 2배 이상을 확인합니다. 조기 관심과 돌파 확인을 별도로 표시합니다. 최근 15분 거래대금 1천만원 미만, 이미 5% 이상 상승, 봉 누락은 제외합니다. 기준 45분 가격 범위는 3% 이하입니다.

이 수치는 검증 전 가설입니다. 점수는 신호 순위용이며 확률이나 세력 매집의 증거가 아닙니다. 1분봉에는 실제 매수/매도 체결 주체·횟수·호가 이력이 없습니다. 기존 96개 압축 패턴은 보존하지만 새 신호 점수에 혼합하지 않습니다. 기존 Python 학습은 저가를 max로 계산하고 브라우저는 min으로 계산한 불일치가 있으므로 그 모델을 새 신호 검증에 사용하지 않습니다.

## 신호 이후 관찰

서버 분석 완료 후 다음 1분봉 시가를 가상 진입으로 사용합니다. 사용자가 화면을 연 시점의 진입가나 실제 주문 체결가가 아닙니다. 30분 동안 +3% 순목표(비용 가정 0.3% 포함 가격 +3.3%)와 가격 -2% 손절선의 선후를 판정합니다. 같은 봉에서 양쪽 도달은 순서 불명으로 기록하고 성공에 포함하지 않습니다. 시간 종료도 별도로 기록합니다. 비용 가정은 실제 체결비용 측정치가 아닙니다.

기본 화면은 서버 누적 기록을 표시합니다(상위 5개에 들지 않은 신호도 포함). 같은 종목·단계는 30분 중복 제한이 있습니다. 서버의 다음 실행에서 평가하며, 지연으로 최근 200봉에 평가 구간이 없으면 그 과거 구간을 별도 조회합니다. API 오류가 난 종목의 대기 기록은 유지합니다. 자료가 실제로 부족하면 누락으로 처리하고 성공·실패 분모에서 제외합니다. 누적 집계는 계속 보존하며 완료된 개별 기록은 최근 1,000건, 미평가 기록은 별도로 보존합니다.

## 서버 감시

`.github/workflows/server-scan.yml`이 표준 GitHub-hosted Ubuntu 서버에서 `scripts/server_scan.cjs`를 실행합니다. UTC cron `2-59/5 * * * *`로 5분 간격을 요청하지만 실행 시각은 보장하지 않습니다. 지연·누락·서비스 제한이 생길 수 있고 초 단위 실시간 감시는 아닙니다. 스캔 중복 실행은 직렬화합니다. 12분 이상 실행은 종료하며 이전 정상 결과를 보존합니다.

`server-data` 브랜치의 `data/server-state.json`에 분석 결과·대기 기록·누적 결과를 저장합니다. 화면을 닫거나 휴대폰을 꺼도 서버가 실행됩니다. GitHub Pages는 GitHub 파일 API로 최신 저장 결과를 5분 간격으로 읽어 표시하며 서버 완료 시각이 10분 이상 오래됐으면 지연을 표시합니다. 화면 자동 갱신을 꺼도 서버 예약은 계속 실행됩니다. API 대규모 오류는 결과를 덮어쓰지 않습니다. 조회한 원화마켓 목록이 비어도 마지막 정상 자료를 보존합니다.

서버 수집은 업비트 공식 API `https://api.upbit.com/v1`에 직접 연결합니다. Cloudflare 중계 요청은 사용하지 않습니다. 3개 동시 요청과 시작 간격 180ms 제한을 적용합니다. 2년치 학습 자료는 재수집하지 않습니다. 표준 실행기를 쓰는 공개 저장소 방식이며 추가 유료 호스팅을 신청하지 않습니다. 푸시 알림과 실제 자동매매는 없습니다. 서버 기록에는 공개 시장 자료와 탐지 결과만 저장하고, 기기의 기존 개인 기록은 업로드하지 않습니다.

웹 브라우저의 별도 Origin 호출 제한 때문에 기기 직접 분석 버튼은 제거했습니다. 앱은 서버 결과만 읽습니다. 서버 수동 실행은 Actions의 Background market scanner에서 Run workflow를 사용합니다.


## 검증

`node --test tests/*.test.cjs`

`node scripts/replay_sequence.cjs candles.json report.json`

입력은 `{ "KRW-BTC": [업비트 1분봉 응답, ...], ... }`입니다. 시간순 마지막 20% 구간에서 고정 규칙과 거래대금 증가율 순위 기준을 비교합니다. 두 방식 모두 같은 유효 데이터·유동성·이미 상승 제외 기준을 씁니다. 같은 시각에 최소 5종목이 있는 구간만 평가합니다. 미래 봉은 신호 입력에 사용하지 않으며 같은 종목의 중복 진입을 30분 제한합니다. 비교 방식은 신호 수가 달라 건수와 적중률을 함께 보아야 합니다. 비용은 고정 가정이며 호가·유동성별 실제 체결은 재현하지 않습니다. 합산 결과는 포트폴리오 수익률이 아닙니다. 홀드아웃 결과를 보고 규칙을 조정하면 새 미사용 평가 구간이 필요합니다.

v51의 실제 시장 과거 재생은 아직 실행하지 않았습니다. 기존 15분봉 압축 모델로 1분봉 순서를 검증할 수 없습니다. 기능 테스트 성공과 투자 성능 검증은 별개입니다.

## 실행

GitHub Pages에서 index.html, app.js, sequence.js 및 기존 스타일·아이콘을 제공합니다. 화면은 서버 결과만 조회하며 시세 API는 GitHub 서버가 직접 호출합니다. 모든 종목을 최대 3개 요청 병렬로 조회하며 요청 시작은 160ms 이상 간격으로 제한합니다. 종목 수와 API 응답 속도에 따라 시간이 걸릴 수 있습니다. 기준 시각이 3분 이상 지난 분석은 지연 표시하고 신규 기록을 제한합니다. API 실패와 봉 누락은 조건 미충족과 구분합니다.
